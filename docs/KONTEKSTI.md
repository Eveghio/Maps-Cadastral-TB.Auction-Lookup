განახლდა: 2026-11-15 · მიმდინარე ვერსია: **DEMO 3.14** (`napr_lookup_DEMO.zip`) · GitHub-ზე გამოქვეყნებული: **3.10**

კოდი: GitHub `Eveghio/Maps-Cadastral-TB.Auction-Lookup`, საქაღალდე `src/` (main). Claude-ის skill: `napr-lookup-extension`. გამოსაშვები ZIP: `python tools/build_zip.py --release`.

## 1. რა არის

გიორგის პირადი Chrome ექსთენშენი (Manifest V3) საკადასტრო კოდებთან სამუშაოდ. ვრცელდება ოჯახსა და მეგობრებში GitHub-ით (`Eveghio/Maps-Cadastral-TB.Auction-Lookup`, `releases/latest/download/napr_lookup.zip`) და `install.bat`-ით; თავად ახლდება.

მუშაობის წესები:
- პასუხები ქართულად, გასაგებად და დეტალურად; შემოთავაზებები მოთხოვნის ფარგლებში.
- **DEMO არ გამოიშვება Release-ად**, სანამ გიორგი არ გატესტავს. კოდი `src/`-ში შეიძლება იყოს DEMO მდგომარეობაში; Release-ის ZIP: `tools/build_zip.py --release` (სახელიდან „DEMO“ იშლება, ფაილი `napr_lookup.zip`).
- კომიტები გიორგის სახელით (Eveghio, noreply ელფოსტა), Claude-ის ხაზების გარეშე.
- ZIP-ში არანაირი ტოკენი ან პირადი მონაცემი. ყველას თავისი ms.gov.ge სესია აქვს.
- მესაკუთრეების სახელები არ ინახება. პირადი ნომრები ისტორიაში ინახება (გიორგიმ იცის).
- პირადი ნომრით ძებნა UI-ში განზრახ არ ჩანს (popup-ის რიგი და კონტექსტური მენიუ მოხსნილია; ისტორიის ფილტრი ჩანს მხოლოდ მაშინ, თუ ისტორიაში ასეთი ჩანაწერია, `ACTIONS_SHOWN_ONLY_IF_USED`): მუშაობს ველში 11 ციფრი + Enter და შორთქათები `1040` / `1050`.
- გარე (CDN) კოდი ბრაუზერში არ იტვირთება. pdf.js ექსთენშენშივე დევს (`lib/`).
- ახალი კოდი იწერება წაკითხვადად: სრული სახელები, ქართული კომენტარები.

## 3. მონაცემთა წყაროები (შემოწმებული)

- **რეესტრის სია:** `https://abstract.reestri.gov.ge/abstract/cad_amo.php?cad_code=<კოდი>`. სტრიქონი = `<tr onclick="openWindow('https://bs.napr.gov.ge/GetBlob?pid=101&bid=…')">`, 4 უჯრა: რეგ. №, განცხადების თარიღი, განაცხადის №, ტიპი (`ამონაწერი` / `საკადასტრო რუკა`). სია **განცხადების** რიგითაა; ყოველი დოკუმენტი ორი ასლით (ხელმოწერილი + ხელმოუწერელი/დაშიფრული). დეტალები: `napr_amonaweri_instruqcia.md` (ვერსია 4).
- **„საკადასტრო რუკა“ ხშირად გეგმა არ არის** (სიტუაციური ნახაზი, შტამპიანი ნახაზი). ამოცნობა: `napr_docs.js` → `describeDoc`.
- **maps.gov.ge:** `POST /map/portal/search` (keyword = კოდი / 11-ნიშნა პირადი № / „lon,lat“); გეომეტრია `geometry_link` (`res=shp`), WKT.
- **ms.gov.ge:** კოდის ძებნა ტოკენის გარეშე მუშაობს; წერტილით: `POST /core-api/v1/search/search-by-xy {lrIds:[261415],x,y,zoom}`.
- **geojson.io:** მონაცემი ბმულით `https://geojson.io/#data=gz:<gzip + base64url GeoJSON>` (მისი „Share“ ღილაკის ფორმატი; ძველი `data:application/json,` აღარ მუშაობს). ხედი: `?map=<zoom>/<lat>/<lon>`, zoom ერთით ნაკლებია სხვა რუკებისაზე. ფერები: simplestyle (`stroke`, `fill`).
- **კოდის regex:** `\d+(?:\.\d+){2,9}[ა-ჰ]?` (3-ნაწილიანი ხაზობრივი ნაგებობები და ბოლოში ქართული ასო).
- ჩვეულებრივი ვებ-გვერდიდან ეს მოთხოვნები CORS-ის გამო არ გადის; მხოლოდ ექსთენშენიდან.

## 4. კონტურების სია (`contours.html`)

- სია **ერთია და გროვდება** (`chrome.storage.session`, გასაღები `contourCollection`): ბრაუზერის დახურვისას ან ღილაკით „სიის გასუფთავება“ იშლება.
- ჩანაწერი: კოდი + „რა გვინდა“: `auto` (maps.gov.ge → ms.gov.ge → ბოლო საკადასტრო გეგმა) ან `plan` + გეგმის ნომერი. სტრიქონში იცვლება ჩამოსაშლელი სიით; ⧉ იმავე კოდის მეორე სტრიქონს ამატებს; ✕ შლის.
- ემატება: ბრძანებით „კონტურები · რუკაზე / KML“, viewer-ის ღილაკით „კონტური რუკაზე (+ სია)“, გვერდის ველით, popup-ის ღილაკით „სია“ (ველში ჩაწერილი კოდები, რუკის გახსნის გარეშე; ცარიელი ველით მხოლოდ სიას ხსნის).
- ms.gov.ge-ს განცხადების პანელი: თითო კონტურს და განცხადებას აქვს „⋯“ მენიუ (ამონაწერი, გეგმა, სიაში, geojson.io, კოპირება; background → `ms-app-contours`). კოდიანი კონტური სიას კოდით ემატება; კოდის გარეშე კი განცხადების პოლიგონით, მზა სახით (`wantedSource: "application"`, წყარო `application`, მწვანე ფერი; წყაროს შეცვლა და ⧉ არ აქვს).
- „წერტილი → კოდი“ ფანჯარას აქვს ღილაკები „სიაში“ და „geojson.io“.
- geojson.io-ზე „Label:“ ავტომატურად „კოდი“ ხდება: geojson.io ამას ბმულით არ იღებს, ამიტომ contours.js (`chooseLabelOnGeoJsonIoPage`) გვერდზე თავად აჭერს ღილაკს და ირჩევს (scripting, `<all_urls>`). label უკვე არჩეულია → არ ეხება.
- „რუკაზე“ მთელ სიას ხსნის geojson.io-ზე. ძველი geojson.io ტაბი იხურება და ახალი იხსნება იმავე ადგილას (geojson.io `#data`-ს მხოლოდ პირველი ჩატვირთვისას კითხულობს, ამიტომ ძველი ტაბის განახლება ახალ კონტურს ვერ აჩენდა). ტაბის ნომერი: `chrome.storage.session` → `contoursGeoJsonIoTabId`. KML ბრძანება მხოლოდ ახალი კოდების ფაილებს იწერს.
- რუკიდან მოსული კონტური ლურჯია, გეგმიდან გამოთვლილი ნარინჯისფერი (მიახლოებითი, გეგმის თარიღის მდგომარეობა).
- გარდაქმნა მხოლოდ გვერდზე მუშაობს (canvas), არა background-ში.

## 5. შორთქათები

Chrome ბრძანებებს id-ით ალაგებს და მომხმარებლის ღილაკს id-ზე ამახსოვრებს. id = `<ჯგუფი><პოზიცია>-<სახელი>`:

| 20 ms.gov.ge | `2010-ms-map`, `2020-ms-map-new-tab`, `2030-ms-kml`, `2040-ms-application-map`, `2050-ms-application-kml` |

## 8. რა არ არის შემოწმებული / ღიაა

- **DEMO 3.11–3.14 გიორგის ჯერ არ გაუტესტავს სრულად** ნამდვილ მონაცემებზე. 3.11: წერტილი → კოდი, პირადი ნომრით ძებნა. 3.12: viewer. 3.13–3.14: კონტურები.
- გეგმის PDF → კონტური ექსთენშენში ნამდვილ გეგმაზე არ გაშვებულა (მხოლოდ სატესტო PDF-ებზე; ნამდვილზე მუშაობს გიორგის HTML). რასტრული გეგმა ექსთენშენში საერთოდ არ გატესტილა.
- PDF-ის ჩვენება viewer-ის შიგნით (iframe) ავტომატურ ტესტში ვერ მოწმდება.
- AES-ით დაშიფრული რეესტრის ფაილი არ შეგვხვედრია (`encrypted-unsupported`).
- შესაძლო შემდეგი ნაბიჯები (არ არის მოთხოვნილი): SHP ფაილი ექსთენშენიდან (`makeShapefile` ბირთვში არის); პირადი ნომრების დაფარვა ისტორიაში.
